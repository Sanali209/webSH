# Критика Архитектуры PC Center OS (v13.0)

## 1. Анализ Single Process Архитектуры (v11.0 - v13.0)

### 🟢 Преимущества
1.  **Простота развертывания:**
    *   Отсутствие Node.js/Nginx/Docker в runtime делает систему доступной для установки на любом устройстве, где есть Python (даже на Android через Termux).
    *   Атомарность обновлений: `git pull` обновляет и бэкенд, и фронтенд сразу.
2.  **Zero-Latency для локальных вызовов:**
    *   Прямой вызов Python-функций через `getattr` внутри одного процесса (v9.0) дает минимальные накладные расходы по сравнению с HTTP/RPC.
3.  **Единая точка входа:**
    *   FastAPI на 8000 порту обслуживает всё, что упрощает настройку CORS и SSL.

### 🔴 Критические Уязвимости и Риски
1.  **Проблема GIL (Global Interpreter Lock):**
    *   Вся система (API, Shell, Plugins) живет в *одном* процессе Python.
    *   **Риск:** Один тяжелый плагин (например, `web_parser` с синхронным парсингом или `deduplicator` с расчетом хэшей в главном потоке) заблокирует Event Loop.
    *   **Результат:** Интерфейс Шелла "замерзнет", API перестанет отвечать.
    *   *Решение:* Жесткое требование выносить CPU-bound задачи в `asyncio.to_thread` или внешний `core.executor` (Taskiq).
2.  **Shared Memory Pollution:**
    *   Плагины загружаются через `importlib` в глобальное пространство имен `sys.modules`.
    *   **Риск:** Плагин A может случайно (или намеренно) пропатчить глобальные объекты, изменить поведение `logging` или конфликтовать версиями зависимостей (Dependency Hell).
    *   *Пример:* Плагин A требует `numpy==1.21`, Плагин B требует `numpy==1.26`. В одном процессе это невозможно.

## 2. Анализ Security Barrier (v12.0 - v13.0)

### 🟢 Преимущества
1.  **UX-Friendly Безопасность:**
    *   Механизм "Аудита и Согласия" (v13.0) понятен пользователю ("Этот плагин хочет в интернет") и не требует знаний Linux Permissions.
2.  **Static Analysis:**
    *   Блокировка по манифесту *до* запуска кода — это мощный превентивный механизм.

### 🔴 Слабые Места
1.  **Python Runtime Introspection:**
    *   Так как нет изоляции процессов (Sandbox), зловредный плагин может использовать `ctypes`, `sys.modules` или `gc.get_objects()`, чтобы обойти `SecurityBarrier`.
    *   *Switchboard Barrier* защищает только от "честных" вызовов через шину. Он не защищает от прямого импорта `os` внутри кода плагина.
    *   **Вердикт:** Это защита от *ошибок*, а не от *злонамеренных атак*. Для полной защиты нужны Docker-контейнеры.
2.  **Token Leakage:**
    *   Передача `session_key` во фронтенд (v12.0) уязвима к XSS. Если в одном плагине есть XSS, злоумышленник может украсть токены других плагинов из `sessionStorage`.

## 3. Анализ Broker / Switchboard (v6.0 - v7.0)

### 🟢 Преимущества
1.  **Decoupling:**
    *   Плагины не знают друг о друге, только о контрактах (Pydantic). Это позволяет менять реализации (например, заменить локальный LLM на OpenAI) на лету.

### 🔴 Риски
1.  **Serialization Overhead:**
    *   Постоянная валидация Pydantic и упаковка/распаковка JSON может стать узким местом при передаче больших объемов данных (видео, аудио, большие векторы).
    *   *Решение:* Использовать `SharedMemory` или передавать ссылки на файлы (File Handles) вместо сырых байтов.

## 4. Рекомендации (Roadmap to Pro)

### Этап 1: Стабилизация Runtime (v13.1)
*   **Watchdog для Event Loop:** Внедрить механизм, который убивает/перезагружает плагин, если он блокирует цикл событий дольше 100мс.
*   **Dependency Isolation:** Использовать виртуальные окружения (`venv`) для каждого плагина, если это возможно, или жестко фиксировать версии библиотек в Core SDK.

### Этап 2: Усиление Безопасности (v14.0)
*   **AST Analysis:** При аудите (Installation Flow) сканировать исходный код плагина (`ast.parse`) на наличие запрещенных импортов (`import os`, `import subprocess`, `eval()`).
*   **Micro-VMs:** Для недоверенных плагинов рассмотреть запуск через **Firecracker** или **WASM** (WebAssembly), что даст реальную изоляцию памяти.

### Этап 3: Производительность
*   **Zero-Copy Transport:** Для передачи данных между плагинами (особенно для AI/Media) использовать Apache Arrow Flight или Python Shared Memory.

## Итоговый Вердикт
Архитектура v13.0 — это отличный баланс для **Personal/SOHO** использования. Она легкая, быстрая и достаточно безопасная для "доверенных" плагинов из официального магазина. Однако для Enterprise-уровня или запуска недоверенного кода потребуется внедрение Docker/WASM изоляции.
