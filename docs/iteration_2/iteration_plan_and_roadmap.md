# План Интеграции и Roadmap Итерации 2

Этот план интеграции переводит архитектуру PC Center v3.0 из теоретической спецификации в практическую реализацию. Мы фокусируемся на превращении Шелла в полноценный оркестратор интерфейса, работающий через ультратонкое ядро.

## Фаза 1: Ядро и инфраструктура раздачи (The Single-Server Core)
**Цель:** Обеспечить работу FastAPI как единого сервера, раздающего статику Шелла и плагинов, а также поддерживающего API Брокера.

### 1. Настройка статических путей (`core/main.py`)
*   **Монтирование скомпилированного Шелла:** `app.mount("/desktop", StaticFiles(directory="dist", html=True))`.
*   **Оптимизация статики (WhiteNoise):** Использование `whitenoise` middleware для production-ready раздачи статических файлов (сжатие, кеширование) вместо стандартного `StaticFiles`, если не используется Nginx.
*   **Динамическое монтирование плагинов:** Цикл при старте в `lifespan`, который итерирует по `loader.loaded_plugins`, находит их директорию `ui` и монтирует по адресу `/plugins/{id}/ui`.
*   **CSP Middleware:** Внедрение Content Security Policy с помощью библиотеки `secure` (или кастомного middleware) для защиты от XSS (запрет inline-скриптов, ограничение доменов).
*   **Health Checks для UI:** Эндпоинт, проверяющий доступность статических файлов плагинов (JS/CSS) после монтирования.

### 2. Реализация UI-Registry в Ядре
*   **Рефакторинг `core/registry.py`:**
    *   Добавить хранилище для UI-компонентов: `self._ui_extensions: Dict[str, List[Dict]]`.
    *   Добавить метод `register_ui_extension(plugin_id, extension_data)`.
*   **Рефакторинг `core/loader.py`:**
    *   В методе `_load_plugin`: парсить `manifest.json` на наличие секции `ui` (или `widgets`/`views`).
    *   **Строгая валидация:** Внедрить JSON Schema валидацию манифеста перед загрузкой. Использовать `pydantic` для определения схемы манифеста. При ошибке валидации плагин помечается как `failed`.
    *   Вызывать `registry.register_ui_extension` при загрузке плагина.
*   **Создание эндпоинта:** `GET /api/v1/registry/ui-extensions`.

### 3. Docker-контейнеризация
*   **Создание Dockerfile:** На базе `python-slim`.
*   **Многоступенчатая сборка (Multi-stage build):** Сначала сборка Svelte-фронтенда Шелла (Node.js), затем копирование в образ с FastAPI.

## Фаза 2: SDK и унифицированные настройки (The Plugin Contract)
**Цель:** Создать стандарт, по которому плагин заявляет свои возможности и интерфейсы.

### 1. Базовый класс BasePlugin (`core/sdk.py`)
*   **Метод `get_settings_model()`:** Возвращает класс Pydantic с настройками.
*   **Метод `get_ui_manifest()`:** Возвращает список виджетов, ссылок и вьюх.

### 2. Генератор схем настроек
*   **Автоматизация:** SDK должен автоматически преобразовывать Pydantic-модель настроек в JSON Schema (используя метод `.model_json_schema()`).
*   **Использование:** Шелл будет использовать эту схему для автоматической генерации форм настроек.

### 3. Декларация UI-элементов в манифесте
*   **widgets:** Список объектов с указанием размера (например, 2x2, 1x4) и точки входа JS.
*   **shortcuts:** Иконка, название и действие (открытие вьюхи).
*   **views:** Полноэкранные SPA-интерфейсы плагина.
*   **Версионирование (`compatibility_version`):** Обязательное поле в `manifest.json`.

## Фаза 3: Разработка системного плагина Shell (The Host)
**Цель:** Создать SPA-приложение, которое выступает в роли рабочего стола.

### 1. Архитектура Шелла (Svelte 5)
*   **State Management:** Использование **Runes** (`$state`, `$derived`) для реактивности. Для глобального состояния использовать легковесную обертку над `localStorage` (например, `@friendofsvelte/state` или кастомный класс на Runes).
*   **UI Manager:** Модуль, отвечающий за синхронизацию состояния.
*   **Error Boundary:** Использование механизмов Svelte 5 (или `try-catch` в `onMount` виджетов) для перехвата ошибок.
*   **Skeleton Loading:** Отображение "скелета" виджета во время загрузки.

### 2. Система нескольких рабочих столов
*   **Sidebar:** Левая скрываемая панель с навигацией по столам.
*   **CRUD:** Механизм создания/удаления столов.
*   **Персистентность (State Persistence):** Сохранение состояния столов в БД (LanceDB/SQLite) через API.

### 3. Desktop Grid (Сетка)
*   **Реализация:** CSS Grid (нативный) или легковесная библиотека.
*   **Drag-and-drop:** `svelte-dnd-action` или нативный HTML5 Drag API.
*   **Dev Mode:** Режим загрузки виджетов с `localhost:3000`.

## Фаза 4: Интеграционные точки и менеджер контента
**Цель:** Реализовать динамическое наполнение Шелла данными сторонних плагинов.

### 1. Top Bar как слот
*   **Сканирование:** Шелл сканирует `ui-extensions` с типом `top_bar.item`.
*   **Импорт:** Динамический импорт JS-кнопок.

### 2. Диалог управления столом
*   **Кнопка в Top Bar:** Открывает модальное окно.
*   **Библиотека Capabilities:**
    *   *Вкладка Виджеты:* Выбор из зарегистрированных в системе виджетов.
    *   *Вкладка Приложения:* Выбор иконок-ссылок.

### 3. Виджеты (Widget Lifecycle)
*   **JS-бандл:** Плагин предоставляет JS-бандл виджета.
*   **Изоляция (Sandboxed Iframe):** Использование библиотеки **`penpal`** для безопасного, основанного на Promise общения с iframe виджета.
*   **Context:** Передача API-токена и ID стола через `penpal` (postMessage).

### 1. Dockerfile для Hugging Face
*   **Порты:** `EXPOSE 7860`. Запуск uvicorn на хосте `0.0.0.0` и порту `7860`.

## Итоговый стек интеграции

| Компонент | Технология | Библиотека/Инструмент (Рекомендация) |
|---|---|---|
| **Backend** | FastAPI (Python) | `fastapi`, `uvicorn`, `whitenoise` (статика), `secure` (CSP) |
| **Shell UI** | Svelte 5 + Vite | Runes (state), `penpal` (iframe comms) |
| **Plugin UI** | Vanilla JS / Svelte | Виджеты и Вьюхи (скомпилированные в ESM) |
| **Contract** | Pydantic | `pydantic` (валидация манифестов и настроек) |
| **Testing** | Playwright | `pytest-playwright` (E2E) |
| **DevOps** | Docker + GH Actions | Docker Hub / HF Registry |
