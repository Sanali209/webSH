# Task 3.4: Slot Registry (UI Injection)

## 1. Вводная часть
Перед началом исполнения: **изучить систему слотов в `docs/DESIGN_EXTENDED.md` раздел 3.1**.

## 2. Инструкция по выполнению
1. Реализовать компонент `Slot.svelte`, который служит точкой входа для UI плагинов.
2. Создать Registry слотов на бэкенде, где плагины заявляют свои намерения (например, "хочу в `sidebar`").
3. Реализовать логику приоритетов для слотов (если на одно место претендуют несколько плагинов).

## 3. Спецификация API (Integration Details)
- **Slot IDs:** `sidebar.bottom`, `toolbar.right`, `file_manager.actions`.
- **Manifest:** `slots: { "sidebar.bottom": { component: "PluginNav.svelte", priority: 10 } }`
- **Registry API:** `GET /api/v1/ui/slots`

## 4. Зависимости (Dependencies)
- Svelte `<svelte:component this={...} />`.

## 5. Принципы кода и архитектуры
- [ ] **Declarative UI:** Плагин не знает "где" он будет, он заявляет "тип слота".
- [ ] **Conflict Resolution:** Сортировка по полю `priority`.
- [ ] **Dynamic Props:** Передача контекста (например, `entity_id`) из слота в компонент плагина.
- [ ] **Loose Coupling:** Смена темы Шелла автоматически применяется к впрыснутым компонентам.

## 6. Безопасность и Валидация
- Проверка разрешений плагина на использование конкретного слота.
- Санитизация впрыскиваемых путей к скриптам.

## 7. Самопроверка (Self-Review)
- [ ] Добавление в манифест записи о слоте sidebar приводит к появлению кнопки в меню.
- [ ] При удалении плагина слот корректно очищается.

## 8. План исполнения
1. [ ] Бэкенд-реестр слотов.
2. [ ] Slot.svelte компонент в Шелле.
3. [ ] Интеграция Priority Logic.

## 9. Цели готовности (Definition of Done)
- [ ] Слоты заполняются динамически.
- [ ] Плагины могут расширять UI системных модулей.
- [ ] Архитектура готова к "Hot Reload" интерфейса.
