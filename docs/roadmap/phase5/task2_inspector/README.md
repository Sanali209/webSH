# Task 5.2: System Inspector (UI Debugger)

## 1. Вводная часть
Перед началом исполнения: **изучить возможности инспектора в `docs/DESIGN.md` раздел 10**.

## 2. Инструкция по выполнению
1. Реализовать плагин `system_inspector`.
2. Создать UI для визуализации:
    *   **Signal Bus Tracker:** Список последних сигналов в реальном времени.
    *   **Slot Map:** Карта занятых и свободных слотов в Шелле.
    *   **Registry View:** Интерактивное дерево всех доступных Capability и их Pydantic-схем.

## 3. Спецификация API (Integration Details)
- **Internal Capability:** `system.inspect` (возвращает статус всех шин).
- **Slot:** Впрыск в `sidebar.bottom` (кнопка Инспектора).
- **Communication:** Использование WebSocket для реал-тайм обновления сигналов.

## 4. Зависимости (Dependencies)
- `svelte-json-tree` (для просмотра JSON схем).

## 5. Принципы кода и архитектуры
- [ ] **Observer Pattern:** Инспектор не должен мешать работе системы (только чтение).
- [ ] **Readonly Access:** Гарантия отсутствия побочных эффектов при инспекции.
- [ ] **Visual Clarity:** Четкое разделение типов сигналов (Call, Event, UI Injection).
- [ ] **Search & Filter:** Возможность фильтрации сигналов по домену.

## 6. Безопасность и Валидация
- Доступность инспектора только в `DEBUG` режиме.
- Скрытие (masking) чувствительных данных мониторинга.

## 7. Самопроверка (Self-Review)
- [ ] При клике на сигнал в списке открывается полный JSON с трассировкой.
- [ ] Slot Map показывает верную иерархию компонентов.

## 8. План исполнения
1. [ ] Бэкенд-эмиттер отладочных данных.
2. [ ] UI таблицы сигналов.
3. [ ] Реализация Slot Map визуализации.

## 9. Цели готовности (Definition of Done)
- [ ] Инспектор — лучший друг разработчика плагинов.
- [ ] Все скрытые механизмы Ядра визуализированы.
- [ ] Ошибки плагинов подсвечиваются в реальном времени.
