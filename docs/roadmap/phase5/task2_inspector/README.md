# Task 5.2: System Inspector (UI Debugger)

## 1. Вводная часть
Перед началом исполнения: **изучить возможности визуализации графов в реальном времени через D3.js**.

## 2. Инструкция по выполнению
1. Реализовать плагин `system_inspector`.
2. Создать UI для визуализации **Signal Call Graph** с использованием **D3.js**.
3. Настроить WebSocket-канал для получения уведомлений о каждом сигнале в Ядре.
4. Реализовать интерактивную карту слотов (Slot Map) для визуального аудита инъекций UI.

## 3. Спецификация API (Integration Details)
- **Signal Tracking:** Подписка на домен `system.trace`.
- **Visualization:** Force-directed graph (D3) для отображения `correlation_id` цепочек.
- **WebSocket:** `ws://kernel/api/v1/debug/stream`.

## 4. Зависимости (Dependencies)
- `d3`, `svelte-json-tree`.

## 5. Принципы кода и архитектуры
- [ ] **Real-time Updates:** Граф должен плавно обновляться при появлении новых сигналов (использование переходов Svelte + D3).
- [ ] **Non-blocking Probe:** Инспектор не должен задерживать выполнение сигналов; данные собираются асинхронно.
- [ ] **Filtering:** Поиск и фильтрация графа по конкретному `trace_id`.

## 6. Безопасность и Валидация
- Доступ только при наличии флага `DEBUG=true`.
- Маскировка содержимого пакетов в UI.

## 7. Самопроверка (Self-Review)
- [ ] При вызове Capability в графе появляется новая нода.
- [ ] Клик по ноде открывает детализацию JSON (через `svelte-json-tree`).

## 8. План исполнения
1. [ ] Backend-стример отладочных данных.
2. [ ] UI графа на D3.
3. [ ] Панель деталей сигнала.

## 9. Цели готовности (Definition of Done)
- [ ] Инспектор — основной инструмент для отладки кросс-плагинового взаимодействия.
- [ ] Визуальный аудит системы работает безупречно.
