# Task 5.1: Plugin SDK & Decorators

## 1. Вводная часть
Перед началом исполнения: **изучить проектную топологию и SDK пример в `docs/DESIGN.md` раздел 9**.

## 2. Инструкция по выполнению
1. Реализовать абстрактный класс `BasePlugin` в `/core`.
2. Создать декоратор `@capability`, который автоматически регистрирует метод в Switchboard.
3. Реализовать методы-хелперы для легкой отправки сигналов и подписки на события.

## 3. Спецификация API (Integration Details)
- **Base Class:** `BasePlugin`
- **Decorators:** `@capability(name, schema?)`, `@on_event(pattern)`
- **Core Methods:** `self.call(domain, params)`, `self.emit(event, data)`, `self.state.subscribe(key)`.

## 4. Зависимости (Dependencies)
- `inspect`, `typing`.

## 5. Принципы кода и архитектуры
- [ ] **Developer Experience:** Минимум кода для создания нового функционала.
- [ ] **Implicit Context:** Автоматическая передача `correlation_id` и `parent_id` при вызовах внутри плагина.
- [ ] **Strict Typing:** Поддержка IDE (Type Hinting) для всех методов SDK.
- [ ] **Lifecycle management:** Хуки `init()`, `start()`, `stop()` внутри класса.

## 6. Безопасность и Валидация
- SDK должен автоматически валидировать входные данные через Pydantic-модели метода.
- Запрет на использование опасных функций (eval, exec) внутри базового класса.

## 7. Самопроверка (Self-Review)
- [ ] Созданный с помощью SDK плагин успешно регистрируется и отвечает на запросы.
- [ ] Автодополнение методов ядра работает в VS Code/PyCharm.

## 8. План исполнения
1. [ ] Реализация BasePlugin.
2. [ ] Разработка системы декораторов через инспекцию методов.
3. [ ] Написание документации к SDK (docstrings).

## 9. Цели готовности (Definition of Done)
- [ ] SDK стабилен и протестирован.
- [ ] Любой новый плагин может быть создан простым наследованиес.
- [ ] API прозрачно и документировано.
