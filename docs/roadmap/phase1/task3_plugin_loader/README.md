# Task 1.3: Plugin Loader & Registry

## 1. Вводная часть
Перед началом исполнения: **детально изучить Handshake Protocol в `docs/DESIGN_EXTENDED.md` раздел 2**.

## 2. Инструкция по выполнению
1. Реализовать сканер директории `/plugins`.
2. Реализовать парсер `manifest.json`.
3. Подключить **Pluggy** для реализации хуков `on_plugin_load`.
4. Реализовать регистрацию Capability и Slot-деклараций в глобальном Registry.

## 3. Спецификация API (Integration Details)
- **Manifest Schema:** Определение полей `id`, `version`, `capabilities`, `slots`.
- **Hooks:** `PLUGIN_HOOKSPEC` для расширения загрузки.
- **Internal Registry:** Индекс доменов в памяти.

## 4. Зависимости (Dependencies)
- `pluggy`, `pydantic`, `importlib`.

## 5. Принципы кода и архитектуры
- [ ] **Dynamic Import:** Использование `importlib` для изоляции загрузки `backend.py`.
- [ ] **Fail Safe:** Если один плагин упал при загрузке, остальные должны загрузиться.
- [ ] **No Side Effects:** Импорт модуля не должен запускать тяжелую логику.
- [ ] **Rich Visualization:** Вывод таблицы плагинов в консоль при старте.

## 6. Безопасность и Валидация
- Проверка структуры манифеста.
- Блокировка плагинов с дублирующимися ID.

## 7. Самопроверка (Self-Review)
- [ ] Положить тестовый плагин в `/plugins` и увидеть его в Registry.
- [ ] Проверить, что хук `on_plugin_load` получает правильные метаданные.

## 8. План исполнения
1. [ ] Модель манифеста на Pydantic.
2. [ ] Динамический импорт и инстанцирование плагинов.
3. [ ] Настройка Pluggy менеджера.

## 9. Цели готовности (Definition of Done)
- [ ] Все доступные плагины зарегистрированы.
- [ ] Ошибки импорта залогированы, но не останавливают ядро.
- [ ] Registry отдает полный список доменов.
