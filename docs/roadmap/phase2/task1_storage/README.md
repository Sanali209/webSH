# Task 2.1: System Storage (LanceDB)

## 1. Вводная часть
Перед началом исполнения: **изучить возможности LanceDB и интеграцию с Apache Arrow в `docs/DESIGN.md` раздел 5.4**.

## 2. Инструкция по выполнению
1. Реализовать плагин `system_storage` на базе **LanceDB**.
2. Создать Pydantic-схемы для хранения: `capabilities`, `logs`, `plugin_state`.
3. Использовать `IVF-PQ` индексацию для векторов Capability (при масштабировании >100k записей).
4. Реализовать батчевую вставку (`batch_insert`) для высоконагруженных потоков логов.

## 3. Спецификация API (Integration Details)
- **Capability:** `storage.get(key)`, `storage.set(key, value)`, `storage.search(vector)`
- **Schema Registry:** Хранение схем сигналов для Switchboard.
- **Provider:** LanceDB (векторный движок).

## 4. Зависимости (Dependencies)
- `lancedb`, `pyarrow`, `pandas`.

## 5. Принципы кода и архитектуры
- [x] **Zero-copy:** Передача данных из LanceDB в Ядро через Apache Arrow без сериализации.
- [x] **Async Native:** Использование асинхронных оберток для I/O операций с диском.
- [x] **Data Locality:** Хранение БД в подпапке `/data` с автоматическим созданием директории.

## 6. Безопасность и Валидация
- Проверка прав плагина на доступ к конкретным таблицам (Namespace isolation).
- Валидация типов данных перед записью в LanceDB.
