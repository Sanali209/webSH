# Task 2.3: mmap Transport

## 1. Вводная часть
Перед началом исполнения: **изучить механизм Shared Memory и Arrow IPC в `docs/DESIGN_EXTENDED.md` раздел 2**.

## 2. Инструкция по выполнению
1. Реализовать механизм `mmap_transport` для передачи больших бинарных данных.
2. Использовать `multiprocessing.shared_memory.SharedMemory` и `SharedMemoryManager` для управления жизненным циклом сегментов.
3. Реализовать чтение Arrow-таблиц напрямую из памяти без десериализации (Zero-copy).

## 3. Спецификация API (Integration Details)
- **Capability:** `transport.alloc(size)`, `transport.free(handle)`
- **Internal:** Маппинг `shm://` URI в системные дескрипторы.

## 4. Зависимости (Dependencies)
- `pyarrow`, `anyio`.

## 5. Принципы кода и архитектуры
- [x] **Zero-copy:** Гарантия 0 операций копирования байтов при передаче от хранилища к плагину.
- [x] **Lifecycle Protection:** Автоматическое освобождение памяти при завершении плагина.
- [x] **Cross-process Safety:** Синхронизация доступа к блокам через системные флаги или события.

## 6. Безопасность и Валидация
- Проверка лимитов выделяемой памяти (Quotas).
- Валидация магических чисел (Magic bytes) в заголовках mmap сегментов.

## 7. Самопроверка (Self-Review)
- [x] Передача 1ГБ данных занимает <1мс (инфо-сигнал с адресом памяти).
- [x] Память корректно освобождается после использования.

## 8. План исполнения
1. [x] Реализация менеджера Shared Memory.
2. [x] Интеграция с PyArrow.
3. [x] Тестирование передачи сегментов между фиктивными процессами.

## 9. Цели готовности (Definition of Done)
- [x] Транспорт готов к передаче тяжелых весов (моделей, баз логов).
- [x] API прозрачно для плагинов.
