# Task 2.3: mmap Transport (Shared Memory)

## 1. Вводная часть
Перед началом исполнения: **изучить раздел 6 в `docs/DESIGN_EXTENDED.md` про Zero-Copy Transport**.

## 2. Инструкция по выполнению
1. Реализовать утилиту для создания и маппинга файлов в памяти (`mmap`).
2. Внедрить поддержку передачи `buffer_id` и `offset` в `CapabilityEnvelope`.
3. Модифицировать `system_storage`, чтобы он мог отдавать большие выборки данных через shared memory.

## 3. Спецификация API (Integration Details)
- **Envelope Extension:** Поля `mmap_ref: { "buffer_id": str, "offset": int, "size": int }`.
- **Internal Utility:** `MmapManager` для аллокации и освобождения буферов.

## 4. Зависимости (Dependencies)
- `mmap`, `os`, `tempfile`.

## 5. Принципы кода и архитектуры
- [ ] **Zero-Copy:** Данные из Arrow-таблиц должны ложиться прямо в mmap-буфер.
- [ ] **Lifecycle Management:** Четкое правило очистки буфера после того, как Consumer его прочитал.
- [ ] **Cross-process safety:** Использование именованных временных файлов для Linux/Windows маппинга.
- [ ] **Graceful Fallback:** Если Shared Memory недоступна, слать данные в JSON Base64.

## 6. Безопасность и Валидация
- Проверка границ (Boundaries check) при чтении из смещения.
- Лимиты на максимальный размер буфера в RAM.

## 7. Самопроверка (Self-Review)
- [ ] Передача 100MB данных занимает менее 50мс.
- [ ] Отсутствуют утечки памяти при интенсивном обмене.

## 8. План исполнения
1. [ ] Ядро менеджера mmap.
2. [ ] Поддержка в формате сигналов.
3. [ ] Реал-ворлд кейс в System Storage.

## 9. Цели готовности (Definition of Done)
- [ ] Большая выборка (10к+ строк) передается мгновенно.
- [ ] Код прошел тесты на стабильность под нагрузкой.
- [ ] Память освобождается корректно.
