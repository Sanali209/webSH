# Task 2.2: System FS Provider (Watchdog)

## 1. Вводная часть
Перед началом исполнения: **изучить роль FS провайдера в `docs/DESIGN.md` раздел 5.4 и механизм индексации в `docs/DESIGN_EXTENDED.md` раздел 4**.

## 2. Инструкция по выполнению
1. Реализовать плагин `system_fs`.
2. Настроить библиотеку **Watchdog** для мониторинга изменений в заданных директориях.
3. Реализовать Capability `fs.scanner` и `fs.watcher` для мониторинга изменений.
4. При нахождении/изменении файла отправлять сигнал `fs.item.modified` через Шину.

## 3. Спецификация API (Integration Details)
- **Emitted Signals:**
    - `fs.item.created` (path, entity_id)
    - `fs.item.modified` (path, hash)
    - `fs.item.deleted` (path)
- **Capabilities:**
    - `fs.scan(path)` -> List[Entity]

## 4. Зависимости (Dependencies)
- `watchdog`, `hashlib`, `mmap`.

## 5. Принципы кода и архитектуры
- [ ] **Event Debouncing:** Игнорировать слишком частые события изменения одного файла.
- [ ] **Resource Safety:** Не держать открытыми файловые дескрипторы дольше необходимого.
- [ ] **Efficiency:** Использовать хеширование только для небольших блоков (через mmap).
- [ ] **Non-blocking:** Сканирование больших дисков должно идти в фоне и слать прогресс.

## 6. Безопасность и Валидация
- Проверка прав доступа к директориям.
- Игнорирование системных и скрытых файлов (напр. `.tmp`, `~lock`).

## 7. Самопроверка (Self-Review)
- [ ] При создании файла в папке Ядро получает сигнал в течение 500мс.
- [ ] Рекурсивное сканирование не зацикливается на символических ссылках.

## 8. План исполнения
1. [ ] Реализация сканера директорий.
2. [ ] Интеграция Watchdog обработчика.
3. [ ] Логика генерации Entity ID для файлов.

## 9. Цели готовности (Definition of Done)
- [ ] Файлы на диске превращаются в Entity в Storage.
- [ ] Реальное время отклика на изменения.
- [ ] Код устойчив к удалению папок во время сканирования.
