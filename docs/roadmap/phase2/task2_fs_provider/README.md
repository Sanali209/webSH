# Task 2.2: System FS Provider (Watchdog)

## 1. Вводная часть
Перед началом исполнения: **изучить структуру системного FS и мониторинг в `docs/DESIGN.md` раздел 5.6**.

## 2. Инструкция по выполнению
1. Реализовать плагин `system_fs_provider` с использованием библиотеки **Watchdog**.
2. Генерировать событие `fs.changed`, когда файл в отслеживаемой зоне изменен.
3. Реализовать "Lazy Hashing": использование сэмпл-хеширования для быстрой проверки контента больших файлов.
4. Использовать `asyncio.Queue` для дебаунсинга и группировки массовых дисковых событий.

## 3. Спецификация API (Integration Details)
- **Capability:** `fs.list(path)`, `fs.read(path)`, `fs.write(path)`
- **Event Out:** `fs.changed(file_path, change_type)`

## 4. Зависимости (Dependencies)
- `watchdog`, `imohash`.

## 5. Принципы кода и архитектуры
- [x] **Non-blocking Watcher:** Мониторинг запускается в отдельном треде, но события пробрасываются в асинхронную шину.
- [x] **Event Debouncing:** Игнорирование промежуточных состояний при сохранении файлов.
- [x] **Strict Paths:** Запрет выхода за пределы разрешенных системных папок (`Sandbox isolation`).

## 6. Безопасность и Валидация
- Экранирование путей для предотвращения Path Traversal.
- Ограничение частоты генерации сигналов при массовых операциях.

## 7. Самопроверка (Self-Review)
- [x] Событие `fs.changed` приходит в консоль при правке файла в `/plugins`.
- [x] Высокая нагрузка (1000 файлов) не вешает Ядро.

## 8. План исполнения

2. [x] Логика фильтрации и дебаунсинга.
3. [x] Реализация методов чтения/записи.

## 9. Цели готовности (Definition of Done)

- [x] Система защиты путей работает.
