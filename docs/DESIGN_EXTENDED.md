# DESIGN_EXTENDED: PC Center OS (v3.0 — The Deep Dive)

Этот документ является расширенной технической спецификацией, детализирующей внутренние механизмы **PC Center OS**. Он предназначен для разработчиков Ядра и сложных системных плагинов.

---

## 1. Switchboard: Матрица Сигналов

Диспетчер сигналов (Switchboard) — это сердце системы. Он не просто пересылает JSON, он управляет состоянием вызова.

### 1.1. Жизненный цикл сигнала (Lifecycle)
1.  **Ingress:** Получение `CapabilityEnvelope` через HTTP POST или WebSocket.
2.  **Audit & Resolve:** 
    *   Аудитор проверяет `caller_id` и `token`.
    *   Registry ищет плагин, предоставляющий `domain@version`.
3.  **Schema Guard:** Валидация `params` через Pydantic-схему, зарегистрированную провайдером.
4.  **Dispatch:** Выполнение вызова. Если провайдер локальный (в том же процессе), вызывается асинхронный метод. Если удаленный — формируется gRPC/HTTP запрос.
5.  **Reactive Update:** Если вызов меняет состояние, бросается событие в `Shared State Store`.
6.  **Egress:** Возврат результата или `parent_id` для асинхронного трекинга.

## 2. Handshake Protocol v3.0 (Registration)

Когда Ядро сканирует папку `/plugins/my_plugin`, происходит «Рукопожатие»:

1.  **Discovery:** Ядро находит `manifest.json`.
2.  **Validation:** Проверка обязательных полей (ID, version, permissions, capabilities).
3.  **Mounting:**
    *   `plugin.backend.py` импортируется.
    *   `plugin/ui/` монтируется в FastAPI: `/plugins/{id}/ui/`.
4.  **Signal Mapping:** Методы, помеченные `@capability`, заносятся в таблицу маршрутизации Registry.

## 3. UI Slot System: Реестр Намерений

Слоты — это не просто места в DOM, это **интерфейсные контракты**.

### 3.1. Типы слотов
*   **Static Slots:** Рендерятся при загрузке Шелла (Sidebar, Navbar).
*   **Dynamic Slots:** Создаются плагинами «на лету» (например, контекстное меню файла).
*   **Singleton Slots:** Может занять только один плагин (например, `media_player.overlay`).

### 3.2. Коммуникация в браузере
Шелл предоставляет глобальный объект `window.pc_center`:
```javascript
window.pc_center.call("domain", params); // Вызов через Ядро
window.pc_center.emit("local_event", data); // Локальная шина (Vite Event Bus)
window.pc_center.store.subscribe("key", callback); // Реактивное состояние
```

### 3.3. Desktop Grid System (Advanced)
Шелл управляет пятью независимыми рабочими столами (**Desktops**).
*   **Grid Layout:** Каждый стол имеет настраиваемую сетку (например, 12x8).
*   **Cell Content:** В ячейку можно поместить:
    *   **Link:** Прямая ссылка на ресурс или файл.
    *   **Icon:** Визуальный маркер с подписью.
    *   **Plugin Shortcut:** Быстрый запуск `Capability` другого плагина.
    *   **Widget:** Динамический UI-компонент плагина.
*   **Widget Contracts:** Виджеты сами декларируют свой размер в сетке (напр. `grid_size: [2, 2]`).
*   **Placement Logic:** Информация о том, какой виджет/ярлык находится на каком столе и в каких координатах, хранится и контролируется исключительно Шеллом (`ui.manager`).

## 4. System FS Provider: Глубинная логика

Этот плагин является «глазами» системы.
*   **Indexing:** Использует `mmap` для быстрого хеширования файлов без полной загрузки в RAM.
*   **Entity Linking:** Файл `invoice_123.pdf` превращается в Entity с ID. Плагин `system_storage` создает для него векторный эмбеддинг.
*   **Events:** Бросает событие `fs.item.modified`, которое слушают плагины ИИ для переиндексации.

---

## 5. Security: The Sandbox Illusion

Так как плагины работают в одном процессе, изоляция — это **логический барьер**.
*   **Namespace Isolation:** Каждый плагин получает свой экземпляр логгера и ограниченный доступ к хранилищу.
*   **Capability Lockdown:** Если плагин не заявил `network.http` в манифесте, Ядро блокирует любые попытки вызова этой способности, даже если вызываемый метод существует.

---

## 6. Транспорт данных (mmap & Arrow)

Для обмена таблицами (например, список из 100,000 файлов):
1.  **Provider:** Создает `mmap` файл или Buffer в памяти.
2.  **Signal:** Передает `buffer_id` и `offset` вместо самих данных.
3.  **Consumer:** Отображает этот же участок памяти в свое адресное пространство.
4.  **Result:** Нулевое копирование (Zero-copy), мгновенный доступ.
